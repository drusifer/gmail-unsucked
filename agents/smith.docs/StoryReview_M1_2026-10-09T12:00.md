# Gate 1 Review: PRD v0.2, Milestone 1 (Filter Editor)
**Reviewer:** Smith · **Verdict:** APPROVED WITH NOTES (non-blocking; fold into AC before Morpheus)
Note: the add-on cannot be run locally; review is of stories plus the existing Code.js card. Real usability testing happens once Neo deploys via clasp.

## Notes (cite heuristic)
1. **F1, #2 Match real world / #8 Minimalist.** "Plain language" is untestable as written. AC must give examples and ordering rules, e.g. `From: boss@x.com -> Label "Work", Skip Inbox, Forward to a@b.com`. Current Code.js prints raw JSON with braces stripped; that is the anti-example. Define a stable sort (e.g. newest first or by first criterion) and pagination/"show more" for long lists (card height is limited).
2. **F3, #5 Error prevention.** Form must (a) require at least one criterion and at least one action (API rejects empty), (b) offer labels from a dropdown of existing labels, never free text, (c) size needs a comparison (larger/smaller) plus a unit, (d) forwarding: dropdown of verified addresses only; unverified addresses are not selectable and a hint explains why. Add Cancel and Back on every form card (#3).
3. **F4, #1/#9 Status and recovery.** Create-then-delete can partially fail. AC: if create succeeds but delete fails, tell the user plainly that a duplicate now exists and offer "Delete old one" retry. Also Gmail may reject an identical filter as already existing; show "No changes to save" rather than a raw API error.
4. **F5, #3 User control.** Confirmation is good, but an Undo (re-create from the captured copy, available right after delete) is better than a modal-ish confirm for a low-frequency destructive action. Recommend: confirm step required, plus "Undo" on the success card.
5. **All stories, #1 Visibility.** AC for loading/empty/error states per card, and a success confirmation after create/edit/delete that returns to the list.
6. **F2 (P1).** Specify that search is case-insensitive, matches the rendered text (what the user sees), and shows "No filters match 'x'" with a clear-search action.
7. **Suggested new story F8 (P1), discoverability:** "As a user reading an email, I can create a filter from this message with sender/subject pre-filled." This is the most common real entry point for filters and the Gmail add-on contextual trigger supports it. Cypher decides scope; Smith recommends P1.
8. **#10 Accessibility.** No color-only state; use text labels in cards.
