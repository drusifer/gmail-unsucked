## Conditions (must be in task list / tests)
1. **C1 Round-trip safety on edit (data loss, heuristic #5/#3).** The internal form model (ARCH section 4) cannot represent everything the API can hold on an existing filter (e.g. multiple `addLabelIds`, extra `removeLabelIds`, `excludeChats`, fields added by Gmail later). Editing such a filter through the form would silently drop those parts. Required: `filterToForm` preserves unrecognized parts and `formToFilter` re-emits them, OR the edit card shows them as read-only text ("Also applies: ...") and says they will be kept. Unit test: edit a filter with an unknown field, assert it survives.
2. **C2 Navigation state.** Preserve search query `q` and `page` across create/edit/delete/undo so returning to the list does not reset the user's place.
3. **C3 Undo scope.** State in AC that Undo exists only on the immediate success card (once). Copy should say so ("Undo" label is enough; no promise of later recovery).
